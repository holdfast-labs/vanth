# Real SSH production validation

`uv run pytest tests/remote/test_live_ssh.py -q -rs` always runs the configuration and response-loss checks. The live case explicitly skips when `VANTH_SMOKE_SSH_TARGET` is absent. `uv run python scripts/real_ssh_smoke.py` prints a JSON skip or pass result and fails on assertions, connection errors, or cleanup errors.

Configure a disposable POSIX SSH host with passwordless bootstrap authentication through the standard OpenSSH key locations, a verified host fingerprint, and this checkout's Vanth installed using `uv`. The Python and helper executable paths must refer to that installation. The bootstrap key must allow shell execution and editing its user's authorized keys; the dedicated key generated by pairing is restricted to the real helper wrapper. Ambient SSH configuration and agents are deliberately excluded by the production transport.

Set all four environment variables; supplying only a target is an error:

| Variable | Value |
| --- | --- |
| `VANTH_SMOKE_SSH_TARGET` | Explicit `[user@]host[:port]` for the disposable host |
| `VANTH_SMOKE_SSH_FINGERPRINT` | Independently verified `SHA256:...` host fingerprint |
| `VANTH_SMOKE_SSH_PYTHON` | Absolute remote Python executable with Vanth installed |
| `VANTH_SMOKE_SSH_HELPER` | Absolute remote `vanth-remote-helper` executable |

One-line Windows cmd example:

```cmd
set "VANTH_SMOKE_SSH_TARGET=testuser@disposable-host:2222" && set "VANTH_SMOKE_SSH_FINGERPRINT=SHA256:verified-fingerprint" && set "VANTH_SMOKE_SSH_PYTHON=/home/testuser/vanth/.venv/bin/python" && set "VANTH_SMOKE_SSH_HELPER=/home/testuser/vanth/.venv/bin/vanth-remote-helper" && uv run pytest tests/remote/test_live_ssh.py -q -rs
```

The harness creates temporary controller state and a fresh remote temporary home, launches its own daemon, performs actual pairing and the forced-command sentinel handshake, starts a workload over SSH, discards its real acceptance reply, and replays the durable request through a fresh SSH connection. It asserts identical job identity and exactly one workload execution, then pushes and pulls a 256 KiB artifact and compares every byte. Finally it revokes only its pairing authorization, stops its isolated daemon through its authenticated shutdown route, and deletes its owned remote directory. It never loads existing controller pairings or uses their dedicated keys. Cleanup failure fails the run.

The injected failure is a lost response after acceptance, rather than a real TCP blackhole during transmission. This exercises production SSH, durable replay, and transfer end to end; it does not certify sshd restarts, arbitrary network partitions, transfer interruption/resume, or a multi-hour remote soak. Those remain separate destructive-network tests for disposable infrastructure.

CI exposes the same live test only through a manual workflow dispatch with `run_real_ssh` enabled. Set repository variables for the four names above and secret `VANTH_SMOKE_SSH_BOOTSTRAP_KEY` for the disposable host's bootstrap private key. No live SSH job runs on pushes or pull requests. The normal test suite retains the explicit skip.

Local availability during implementation: Docker's Linux engine was unavailable, and the installed WSL Ubuntu distribution had Python but no `sshd` or `uv`. No SSH host was provisioned or modified, so the live case was not executed locally.
